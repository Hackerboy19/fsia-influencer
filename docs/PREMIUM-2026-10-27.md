# Premium design pass, 27 October 2026

Builds on PR #5 (branch `claude/project-thread-xyhtx0`). Same routes, APIs, data structures and forms. New branch, so it gets its own Vercel preview.

## Main problems found

1. Home page: the hero photos were three different crops placed unevenly, and the search was a thin bar.
2. Creator profiles were not the centre of the page: one plain 4-column grid, then two long lists (category, city) of 15+ rows.
3. "For creators" and "For brands" were two short paragraphs. They did not say what happens after you apply or send an enquiry.
4. "How a profile gets here" did not separate what the creator supplies from what the team checks.
5. Award section mixed confirmed benefits with optional services (branding support, brand introductions) in one list.
6. "Also on the site" repeated links that are already in the menu and footer.
7. If `/api/creators` hung (no error, no reply), pages stayed on "Loading profiles…" forever.
8. Profiles without a photo showed a large empty frame with initials.
9. Directory: category was a dropdown only; result count did not say how many are shown.

## SEO and rendering findings

- Page copy, headings, forms and footer are in the first HTML (prerendered). Profiles are not: they come from the live database through `/api/creators` after the page loads, so the first HTML shows a loading skeleton. Real profiles in the first HTML would need the PHP host to render them (or a build step that reads the live database). Not done here.
- Individual profiles use `/talent/?profile=slug`, which has the directory canonical, so profiles are not indexed as separate pages. Separate profile URLs would need server routes.

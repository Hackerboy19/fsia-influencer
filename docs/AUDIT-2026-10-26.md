## Evidence by requirement

**1–2. UI, text, footer, mobile.** The ink colours are #1B1A17 / #45423C / #625E56 on #F7F5F0, at least 5.9:1 contrast. axe-core WCAG 2.2 AA found no violations on any route at any size. There is no horizontal overflow at 390, 768 or 1440 px. The footer is dark (#1B1A17) with #E7E3DA links and is aligned in 4 columns on desktop and stacked on phones. The phone menu opens as a dialog, traps focus, closes with Escape, marks the current page and links every section. Form labels sit above full-width fields; errors show next to the field, set `aria-invalid` and move focus to the first wrong field.

**3. "Forever".** I searched case-insensitively, including encoded spellings. None found in the built HTML, JS, CSS, sitemap, robots.txt, JSON-LD, OG tags, share image text, or the public API responses. The word appears only in source-code comments and in the server filter that removes it from stored text, which is not public output.

**4. Metadata.** Every page has its own title and description, a canonical URL on https://influencer.fsia.in, `index, follow` (admin: `noindex, nofollow`), og:title/description/url/image (1200×630) and Twitter card. JSON-LD has Organization, WebSite, WebPage and BreadcrumbList; /faq/ adds FAQPage. There are no ratings, reviews or invented facts. Titles and descriptions are unique (audit check).

**5. Initial HTML (fixed).** Before: each page's HTML held only the heading, one paragraph and links, and the rest needed JavaScript. Now: at build time, `scripts/render-app.tsx` renders the real app for each route into its `index.html`, including the header, all page copy, forms, FAQ answers and footer. Profiles, campaigns and plans come from the live database, so they still load in the browser. The 3D gallery and admin keep the short summary. I checked with JavaScript turned off: home and /join/ display complete, styled pages.

**6. Sitemap and robots.** `/sitemap.xml` returns 200 on the preview and locally, with 10 public URLs. They match the canonicals; admin is excluded. `/robots.txt`: `Allow: /`, `Disallow: /admin/`, sitemap line. The preview copies point at influencer.fsia.in, as they should.

**7. Google.**
- **GA4:** the only ID is G-H2EP91PV1E. It loads once per page with one config call (audit check).
- **GTM:** none on this site, on purpose; GTM-T3674CM belongs to www.fsia.in.
- **Search Console:** no verification tag is in the code. The build adds one if you run `GSC_VERIFICATION=<token> npm run package`. I have no access to your Search Console, so verification, sitemap submission and indexing are **NOT VERIFIED**. I am not claiming any indexing.

**8. Forms.** All tested end to end against the PHP API: registration (3 steps), brand enquiry, campaign application, membership request, contact and magazine booking. Each one checks:
- the API rejects bad email or phone (400) and oversized requests (413);
- the browser shows a clear error;
- typed data survives a server failure;
- a double click sends one request;
- a success screen shows a reference;
- each record appears in Admin;
- after 12 submissions in 10 minutes a visitor is limited (429).

**Not verified on the live site.** Vercel previews have no PHP backend, so forms there always fail. That is expected, not a bug.

**9. Discovery.** Search, category and city filters update the URL. Sort works, and the empty state says "No profiles match these filters". A profile opens with `?profile=` so the link can be shared, and Back or Escape closes it. No JavaScript errors appeared on any route (only blocked external fonts and photos in my sandbox).

## Blockers that need you (not changed by me)

Some profile roles say "Winner, Miss India 2026" or "1st Runner Up, Miss India 2026". Those names show in Home's "Browse by category", the Profiles category filter, profile cards and the 3D gallery. That conflicts with "only one award category". This is your data, so I did not rewrite it. Please rename the sections in Admin (for example by niche: Fashion, Lifestyle) and edit those roles, or tell me what to change them to. My local copy uses the repo's seed data; please check what your live database has.
2. **Sample campaigns.** The seed data has 4 campaigns naming Sabyasachi, Taj, Vogue India and OnePlus, including "Direct verified star bank wire escort". If they are on the live site and not real, delete them in Admin → Campaigns.
3. **Final site and award names.** "Influencer Awards" and "Influencer Award" are placeholders. The logo and favicon still show an "F" mark from the old brand, which should change with the final name.
4. **Privacy policy and terms.** None exist, so the footer has no links to them.
5. **Search Console.** Send the verification token (or verify by DNS), then submit `https://influencer.fsia.in/sitemap.xml`.
6. **Live check.** After you upload the zip, run `npm run audit -- https://influencer.fsia.in` from a computer that can reach the site. My sandbox can't.
7. **Profiles as their own pages.** Profiles open as overlays on /talent/, so search engines can't index each one. Giving each profile its own URL would need the PHP host to serve per-profile pages. That is a bigger change, which I can do if you want it.
